# 公告、活动与优惠券模块设计方案

> 文档类型：运营内容与营销权益方案

> 编制日期：2026-10-10

> 实施状态：**方案设计，待开发验证**

> 适用项目：游戏陪玩系统

> 设计依据：当前工作区代码、《需求分析说明书.md》《详细设计说明书.md》以及现有公告、订单和虚拟钱包实现

## 1. 设计结论

平台运营内容分为三个相互关联、职责不同的部分：

| 模块 | 职责 | 当前状态 |
|---|---|---|
| 平台公告 | 发布平台规则、系统维护和重要通知 | 已有后端生命周期和管理页面 |
| 平台活动 | 展示运营活动、活动详情和入口 | 首页目前使用前端静态数据 |
| 优惠券 | 活动可发放、用户可领取并在订单中抵扣的营销权益 | 当前尚未实现 |

优惠券应作为独立业务模块实现，通过 `activity_id` 与活动关联，通过订单快照进入下单和支付链路。不能只在活动页面增加一个静态优惠文案，否则无法保证库存、有效期、重复使用和金额结算的一致性。

本方案首期只实现平台补贴型优惠券，不实现会员、积分、裂变、抽奖和多券叠加。

## 2. 当前实现基线

### 2.1 公告

现有公告模块位于 `backend/src/main/java/com/gameplay/announcement`，已支持：

- 草稿、已发布、已撤回三种状态；
- 管理端新增、编辑、发布、撤回和删除草稿；
- 游客访问已发布公告列表和详情；
- 前端管理页 `/admin/announcements`；
- 首页通过 `/api/announcements` 展示公告。

公告状态机为：

```text
DRAFT -> PUBLISHED -> REVOKED
```

### 2.2 活动

首页 `frontend/src/views/user/HomeView.vue` 中的活动轮播当前使用静态数组，包含新人福利、周末活动、陪玩师招募和评价奖励等展示内容。后续应改为活动公开接口和活动详情页，避免活动内容只能修改前端代码。

### 2.3 订单和钱包

当前订单创建流程在 `OrderService.createOrder` 中计算服务金额，`PlayOrder.totalAmountCents` 同时用于用户支付、退款和陪玩师结算；`WalletService.pay` 按该字段扣款，`WalletService.settle` 按该字段结算陪玩师收益。

优惠券接入后必须区分：

```text
优惠前金额 = 用户选择的服务原价
优惠金额 = 平台承担的优惠金额
实付金额 = 用户钱包实际扣款金额
结算金额 = 陪玩师应得金额
```

默认规则为平台承担优惠，陪玩师按优惠前金额结算。

## 3. 目标与非目标

### 3.1 目标

1. 管理员可以创建、发布、下线和查询优惠券模板。
2. 用户可以从活动页或优惠券中心领取优惠券。
3. 用户在创建预约订单时可以选择符合条件的优惠券。
4. 后端重新计算优惠金额，前端金额只用于展示。
5. 订单保存优惠券和金额快照，支付、退款、结算可以追溯。
6. 并发领取、并发使用和重复支付不会造成超发、重复扣款或重复使用。

### 3.2 首期不做

- 优惠券叠加使用；
- 会员专属价和积分抵扣；
- 拼团、裂变、抽奖和邀请奖励；
- 自动返现和真实支付渠道；
- 陪玩师自行创建优惠券；
- 按优惠券承担方拆分复杂平台和陪玩师分账。

## 4. 业务模型

### 4.1 优惠券模板

优惠券模板由管理员维护，描述一类可以被发放给用户的权益。模板包含优惠规则、适用范围、有效期和数量限制。

首期支持两种类型：

| 类型 | 例子 | 计算方式 |
|---|---|---|
| `FIXED` | 满 100 元减 20 元 | `min(优惠金额, 原价 - 1 分)` |
| `DISCOUNT` | 满 100 元享 8.5 折 | `min(原价 × 0.85, 最高优惠限制)` |

折扣比例使用整数基点保存，例如 `8500` 表示 8.5 折，避免使用浮点数。

适用范围首期支持：

| 范围 | 含义 |
|---|---|
| `ALL` | 平台所有可预约服务 |
| `GAME` | 指定游戏下的服务 |
| `SERVICE` | 指定陪玩服务项目 |
| `COMPANION` | 指定陪玩师的服务 |

### 4.2 用户优惠券

用户领取模板后生成独立的用户优惠券记录。用户优惠券保存领取时的有效期快照，模板后续修改不会影响已领取优惠券。

用户优惠券状态：

```text
AVAILABLE -> LOCKED -> USED
AVAILABLE -> EXPIRED
LOCKED -> AVAILABLE       未支付订单取消或支付超时
```

`USED` 为终态。首期订单完成退款时默认不恢复已使用优惠券，避免优惠券被重复套利；如后续需要支持退款返券，再增加 `RETURNED` 状态和返券策略。

### 4.3 领取和使用规则

- 只有 `PUBLISHED` 状态且处于有效期内的模板可以领取。
- 总发行量为 `0` 时表示不限量，否则领取时必须原子校验剩余数量。
- 每个用户的领取数量不得超过 `per_user_limit`。
- 一张用户优惠券只能锁定一个未支付订单。
- 订单创建时锁定优惠券，支付成功时标记为已使用。
- 未支付订单取消、支付超时或创建事务回滚时释放优惠券。
- 下单和支付接口都必须重新校验优惠券，不能只相信前端预览结果。
- 一个订单首期只允许使用一张优惠券。

## 5. 模块关系

```text
管理员后台
  ├─ 公告管理：规则、维护、运营通知
  ├─ 活动管理：活动展示、详情、运营入口
  └─ 优惠券管理：规则、库存、有效期、发放状态
          │
          ├─ 活动关联优惠券模板
          └─ 用户领取 -> 用户优惠券
                              │
用户选择服务 -> 预览优惠 -> 创建订单锁定优惠券 -> 模拟支付使用
                              │
                 订单金额快照 / 钱包扣款 / 陪玩师结算
```

## 6. 数据库设计

### 6.1 优惠券模板表

建议新增 `coupon_template`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键 |
| `name` | VARCHAR(100) | 优惠券名称 |
| `coupon_type` | VARCHAR(20) | `FIXED` 或 `DISCOUNT` |
| `threshold_cents` | BIGINT | 使用门槛，单位分，0 表示无门槛 |
| `discount_cents` | BIGINT | 满减金额 |
| `discount_rate_bp` | INT | 折扣基点，8500 表示 8.5 折 |
| `max_discount_cents` | BIGINT | 折扣券最高优惠，0 表示不限制 |
| `scope_type` | VARCHAR(20) | `ALL`、`GAME`、`SERVICE`、`COMPANION` |
| `scope_id` | BIGINT | 适用目标 ID，`ALL` 时为 0 |
| `activity_id` | BIGINT | 关联活动 ID，可为空 |
| `total_quantity` | INT | 总发行量，0 表示不限 |
| `claimed_quantity` | INT | 已领取数量 |
| `per_user_limit` | INT | 每人限领数量 |
| `valid_from` / `valid_until` | DATETIME | 有效期 |
| `publish_status` | VARCHAR(20) | `DRAFT`、`PUBLISHED`、`OFFLINE` |
| `created_by` / `published_by` | BIGINT | 管理员 ID |
| `published_at` | DATETIME | 发布时间 |
| `created_at` / `updated_at` | DATETIME | 审计时间 |

建议索引：

```text
(publish_status, valid_from, valid_until)
(activity_id)
```

### 6.2 用户优惠券表

建议新增 `user_coupon`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键 |
| `template_id` | BIGINT | 优惠券模板 ID |
| `user_id` | BIGINT | 用户 ID |
| `coupon_code` | VARCHAR(64) | 用户优惠券唯一编码 |
| `status` | VARCHAR(20) | `AVAILABLE`、`LOCKED`、`USED`、`EXPIRED` |
| `valid_from` / `valid_until` | DATETIME | 有效期快照 |
| `locked_order_id` | BIGINT | 当前锁定订单 ID |
| `used_order_id` | BIGINT | 已使用订单 ID |
| `claimed_at` | DATETIME | 领取时间 |
| `locked_at` / `used_at` | DATETIME | 锁定和使用时间 |
| `created_at` / `updated_at` | DATETIME | 审计时间 |

建议索引：

```text
UNIQUE(coupon_code)
(user_id, status, valid_until)
(locked_order_id, used_order_id)
```

### 6.3 订单金额字段

在 `play_order` 中增加：

| 字段 | 说明 |
|---|---|
| `original_amount_cents` | 优惠前金额 |
| `discount_amount_cents` | 优惠金额 |
| `coupon_id` | 使用的用户优惠券 ID |
| `coupon_name_snapshot` | 优惠券名称快照 |
| `settlement_amount_cents` | 陪玩师结算金额 |

现有 `total_amount_cents` 保留为用户实付金额，兼容当前支付、订单列表和余额校验逻辑。

金额约束：

```text
0 <= discount_amount_cents < original_amount_cents
total_amount_cents = original_amount_cents - discount_amount_cents
settlement_amount_cents = original_amount_cents  （平台承担优惠时）
```

## 9. 订单、支付和退款时序

### 9.1 创建订单

```text
校验服务和档期
  -> 计算优惠前金额
  -> 锁定用户优惠券
  -> 校验门槛、范围和有效期
  -> 计算优惠金额
  -> 写入订单金额和优惠券快照
  -> 写入临时档期
  -> 提交事务
```

如果任何一步失败，订单和优惠券锁定必须一起回滚。

### 9.2 支付

```text
锁定订单
  -> 确认订单仍为待支付
  -> 确认优惠券为 LOCKED 且属于当前订单
  -> 钱包扣除 total_amount_cents
  -> 优惠券改为 USED
  -> 订单进入待接单
```

钱包流水业务号仍使用订单号保证支付幂等，例如：

```text
PAY:<orderNo>
```

### 9.3 未支付取消和超时

未支付订单取消或支付超时：

```text
订单关闭 -> 释放临时档期 -> LOCKED 优惠券恢复 AVAILABLE
```

定时任务和用户主动取消都必须调用同一个释放方法，避免出现两套不一致的优惠券状态逻辑。

### 9.4 已支付退款和结算

- 全额退款退回用户实际支付金额 `total_amount_cents`。
- 部分退款金额不能超过实际支付金额。
- 已使用优惠券默认保持 `USED`，不自动恢复。
- 陪玩师收益结算使用 `settlement_amount_cents`，平台承担的优惠不从陪玩师收益中扣除。

## 11. 安全、一致性和异常处理

1. 优惠金额由后端计算，禁止信任前端提交的折扣金额。
2. 领取数量通过原子更新或行锁控制，不能先查询再普通更新。
3. 使用优惠券时锁定用户优惠券行，防止同一张券被两个订单同时使用。
4. 支付、优惠券使用和订单状态迁移必须位于同一事务边界内。
5. 所有金额使用整数分，折扣使用整数基点，不使用浮点数。
6. 订单详情和订单列表只返回当前用户有权限查看的优惠快照。
7. 优惠券模板下线后，已领取且仍在有效期内的用户优惠券默认继续可用；如业务要求立即失效，应增加明确的批量失效策略。
8. 用户重复领取必须返回稳定业务错误，不生成第二张用户优惠券。
9. 订单创建失败不能留下 `LOCKED` 优惠券。
10. 接口错误码应区分模板不存在、未发布、已过期、未达到门槛、范围不适用、库存不足和优惠券已使用。

## 12. 验收标准

### 12.1 管理端

- 管理员可以新增优惠券草稿。
- 草稿可以编辑和删除，已发布模板不能直接编辑。
- 发布后用户可以领取，未发布和已下线模板不可领取。
- 数量限制、每人限领和有效期筛选正确。
- 活动可以关联优惠券领取入口。

### 12.2 用户端

- 用户可以查看可用、已使用和已过期优惠券。
- 只有符合门槛和适用范围的优惠券会被推荐。
- 创建订单后订单中保存优惠券和金额快照。
- 首页、订单列表和支付页金额显示一致。
- 未支付订单取消后优惠券可以重新使用。
- 同一张券不能被重复使用。

### 12.3 资金和并发

- 钱包扣除实际支付金额。
- 陪玩师结算按平台规则使用结算金额。
- 退款不超过用户实际支付金额。
- 重复支付只扣款一次。
- 并发领取不会超过总发行量。
- 并发使用同一张券最多一个订单成功。

```text
  - 支付成功标记 USED
  - 未支付取消释放优惠券
  - 重复支付幂等
  - 并发库存和并发使用
  - 优惠后支付、退款和结算金额核对
```

前端至少验证：

- 创建预约页优惠券选择和金额预览；
- 支付页金额快照；
- 活动页领取按钮；
- 我的优惠券空状态、加载失败和过期状态；
- 管理端表格、弹窗、分页和状态按钮；
- 移动端金额区域不溢出。

## 13. 实施顺序

1. 增加数据库表和订单金额字段。
2. 实现优惠券领域模型、状态枚举、Mapper 和服务层。
3. 实现用户领取、查询和优惠预览接口。
4. 将优惠券锁定接入订单创建，将使用接入支付，将释放接入取消和超时任务。
5. 调整钱包支付、退款和陪玩师结算金额口径。

| 决策项 | 本方案默认值 |
|---|---|
