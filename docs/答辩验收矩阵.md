# 答辩验收矩阵

## 演示账号

| 角色 | 准备方式 | 验证重点 |
|---|---|---|
| 普通用户 | 注册后充值演示余额 | 浏览、预约、支付、确认、评价、投诉 |
| 陪玩师 | 普通用户提交入驻申请，管理员审核 | 服务、档期、接单、开始/结束、收益 |
| 管理员 | `sql/data.sql` 预置账号 | 审核、投诉仲裁、用户和公告管理 |
| 客服 | 管理员创建客服账号 | 队列、领取会话、消息、转人工、关闭 |

## 核心链路

1. 用户注册并登录，浏览游戏和陪玩师服务。
2. 用户创建订单，支付成功后确认钱包余额和支付流水只增加一条。
3. 陪玩师领取订单，开始服务并结束订单。
4. 用户确认完成，检查陪玩师收益结算和订单状态。
5. 用户提交评价；异常订单进入投诉处理并验证退款金额。

## 异常分支

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 余额不足 | 余额小于订单金额时支付 | 返回 `WALLET_BALANCE_INSUFFICIENT`，订单保持待支付 |
| 档期冲突 | 两个用户预约重叠时段 | 最多一个订单创建成功，另一个返回 `SLOT_CONFLICT` |
| 重复支付 | 对同一订单连续点击支付 | 只扣一次余额，只产生一条 `PAY:` 流水 |
| 越权访问 | 修改 URL 中的订单、会话或用户 ID | 返回权限错误或资源不存在，不泄露他人数据 |
| 投诉退款 | 重复提交全额或部分退款 | 退款流水幂等，不重复增加余额 |

## 证据要求

- 保存登录、订单状态、钱包流水和投诉处理页面截图。
- 记录前端浏览器控制台、后端日志和数据库关键查询结果。
- 每个失败项记录复现步骤、接口路径、错误码和修复提交。
