# 部署与故障排查

## 推荐启动方式

正式演示优先使用 Nginx 同源代理；本机直接启动 Spring Boot + Vite 作为备用方案。

### 后端

```powershell
$env:SPRING_PROFILES_ACTIVE="demo"
$env:DB_USERNAME="root"
$env:DB_PASSWORD="本机数据库密码"
$env:JWT_SECRET="至少 32 字节随机字符串"
$env:APP_CORS_ALLOWED_ORIGINS="http://localhost"
$env:FILE_STORAGE_DIR="D:\bishe\游戏陪玩系统\uploads"
cd backend
mvn spring-boot:run
```

### 前端

```powershell
cd frontend
npm install
npm run build
npm run preview -- --host 0.0.0.0
```

Nginx 将 `/api` 和 `/ws/cs` 转发到 `127.0.0.1:8080`，前端静态文件使用同一域名提供，演示环境的 CORS 来源设置为该域名。

## 故障排查

| 现象 | 优先检查 |
|---|---|
| 登录返回 401 | `JWT_SECRET` 是否已设置，账号是否被禁用，浏览器是否保留旧令牌 |
| 页面接口跨域 | `APP_CORS_ALLOWED_ORIGINS` 是否包含当前前端来源，Nginx 是否同源转发 |
| WebSocket 断开 | `/ws/cs` 是否启用 Upgrade/Connection 转发，令牌是否有效 |
| 上传失败 | 文件扩展名、真实大小、`FILE_STORAGE_DIR` 权限和磁盘空间 |
| 订单无法支付 | 用户余额、订单状态、陪玩师档期和数据库唯一键 |
| 定时任务未执行 | Spring 应用是否启动，订单截止时间是否已到，检查 `com.gameplay` 日志 |

演示前执行 `npm run build` 和后端 `mvn test`，并按《答辩验收矩阵》完成一次完整链路验收。
