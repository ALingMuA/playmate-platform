# AI 客服接入与验收

## 接入方式

后端通过 SenseNova 的 Chat Completions 兼容接口调用模型。管理员维护的知识条目用于回答依据；本会话最近几轮用户和 AI 消息用于连续追问。模型只提供咨询，退款、投诉仲裁、改单等操作仍进入人工流程。

默认服务地址为 `https://token.sensenova.cn/v1`，默认模型为 `sensenova-6.8-flash-lite`。模型 ID 应以当前账号已开通的模型为准，可在管理员「AI 接口配置」页面替换并测试。此处使用 API Key 鉴权的兼容接口，不使用旧版 Access Key/Secret Key 生成令牌的接口。

官方参考：[SenseNova API 接入文档](https://github.com/OpenSenseNova/SenseNova6.8/blob/main/API_CN.md)。

## 管理员配置入口

登录管理员账号，进入 **管理后台 → AI 接口配置**（`/admin/ai-settings`）。本机配置与环境变量作为默认值，管理员保存的数据库配置优先。数据库配置保存后对新请求立即生效，正在执行的模型请求使用开始时的配置快照。页面「恢复本机配置」可清除数据库覆盖项，恢复启动时读取的本机配置。

页面支持：启停、基础地址与请求路径、完整请求 URL（优先，可携带 `api-version` 等非敏感查询参数）、模型名称、Bearer / 自定义密钥头 / 无认证、API Key、连接超时、请求总超时、输出 token 上限及对应字段名、历史消息数、可选温度、附加请求头和扩展 JSON 参数。只兼容 OpenAI Chat Completions 协议，不能仅换地址就调用其他原生协议。

- 总超时 1–120 秒，连接超时 1–30 秒；输出上限 64–32768，历史消息 0–50 条，温度 0–2 或不发送。
- `max_tokens` / `max_completion_tokens` 由模型支持情况选择。`thinking`、`reasoning_effort`、`top_p` 等可在扩展 JSON 中填写；这些参数并非所有模型都支持。
- 核心字段 `model`、`messages`、`stream` 等由程序生成，扩展字段不能覆盖这些约束或开启工具调用。
- 外部接口须 HTTPS，本机调试允许 localhost / 127.0.0.1 的 HTTP。URL 不允许嵌入认证信息，密钥应填认证栏或附加请求头。
- 密钥和附加请求头值不回显、不写前端本地存储。密钥留空保留旧值，清除必须显式选择；已保存请求头留空保留值，移除条目才删除。
- 「测试当前草稿」通过真实客服客户端发送固定问候并校验回答格式，消耗少量模型额度，不保存配置、不创建客服会话，也不发送业务资料。测试后点「保存配置」才生效；上游网络失败不会改写原配置。
- 页面展示 HTTP 状态、耗时和稳定错误类别，不显示提供商原始错误正文，避免回显请求凭据。配置版本用于阻止两个管理员互相覆盖。
- 已经转人工的会话不会重新进入 AI 流程，保存配置后请新建会话验证。

全部配置使用 AES-256-GCM 加密后保存到 `ai_model_settings`。加密主密钥可由后端环境变量 `AI_CONFIG_ENCRYPTION_KEY` 提供（至少 32 字节），未指定时从现有 `jwt.secret` 派生。主密钥不要放入管理页面或 Git；更换主密钥会使旧密文无法解密，部署时应保持它稳定。管理员审计仅记录动作和版本，不保存配置原文。数据库覆盖配置生效时，更改本机 YAML 或环境变量不会覆盖它；需先恢复本机配置。

## 数据库升级

已有数据库使用 `sql/migrations/20260908_ai_model.sql` 升级一次。执行前备份数据库，在 `game_companion_app` 中执行该脚本。该脚本只新增 `ai_reply_task` 表和 `ai_call_log` 的模型、用量、错误分类字段，不删除会话和消息。

已完成上述升级的数据库，再执行 `sql/migrations/20260913_ai_settings.sql` 新增管理员配置表。该脚本可重复执行，不删除现有数据。

新数据库直接执行更新后的 `sql/schema.sql` 和 `sql/data.sql`，不需要重复执行升级脚本。已有数据库不要重新运行全量初始化脚本。

## 本机配置

在后端启动进程的环境变量中配置以下项目。可以使用 IntelliJ IDEA 的运行配置，或者当前 PowerShell 会话的环境变量。密钥只保存在本机受控配置中，不写进代码、前端、共享运行配置或 Git。

| 环境变量 | 说明 | 默认值 |
|---|---|---|
| `AI_MODEL_ENABLED` | 是否调用真实模型 | `false` |
| `SENSENOVA_API_KEY` | SenseNova 控制台创建的 API Key | 无 |
| `AI_MODEL_API_KEY` | 可选的通用密钥配置，优先于上一项 | 无 |
| `AI_MODEL_BASE_URL` | 接口根地址，不含 `/chat/completions` | `https://token.sensenova.cn/v1` |
| `AI_MODEL_NAME` | 已开通的模型 ID | `sensenova-6.8-flash-lite` |
| `AI_MODEL_TIMEOUT_SECONDS` | 单次模型请求总时限，单位秒 | `25` |
| `AI_MODEL_MAX_OUTPUT_TOKENS` | 请求的输出 Token 上限 | `800` |
| `AI_MODEL_HISTORY_MESSAGES` | 上下文最多保留的历史消息条数 | `12` |
| `AI_CONFIG_ENCRYPTION_KEY` | 数据库配置加密主密钥（可选） | 从 `jwt.secret` 派生 |

配置密钥后将 `AI_MODEL_ENABLED` 设为 `true`，重启后端。关闭该开关时使用本地知识库，不会请求外部模型。真实模型不可用时，可靠知识条目可作为兜底，否则提示并转人工；不能把这类回复当成真实模型调用成功。

前端仍通过本项目的后端访问客服功能，不直接访问 SenseNova。请求只发送必要的脱敏上下文，不发送客服内部备注或其他用户的资料。模型推理字段不显示、不记录。

## 消息与任务

用户消息保存后创建回复任务并立即确认接收，后台生成完整回答后推送。生成过程不占用数据库事务，也不阻塞 WebSocket 消息处理线程。

| 状态 | 含义 |
|---|---|
| `PENDING` | 等待后台处理 |
| `RUNNING` | 正在调用 AI 应答流程 |
| `COMPLETED` | 正常完成 |
| `FALLBACK` | 使用兜底回答 |
| `FAILED` | 任务异常或过期，结束等待并执行兜底处理 |
| `CANCELLED` | 会话已转人工或关闭，取消 AI 回复 |

`clientMsgId` 用于消息重放去重，任务关联源消息。刷新或断线重连后，通过会话详情中的 `aiTask` 恢复状态，通过消息游标补拉缺失内容。生成期间转人工后，迟到的 AI 结果不再插入会话。

首期展示完整回答，不做逐字流式输出。知识检索使用现有关键词数据，不依赖向量数据库。引用校验能确认模型引用的条目来自本次检索，但不能证明回答中的每一句自然语言都正确，答辩前仍需准备业务问答验收集。

单进程执行器最多同时生成 2 个回答，内存等待位为 16。持久活跃任务上限默认 100，每用户每分钟默认最多 12 次；后两项通过入队计数控制，不属于严格的分布式限流。`PENDING` 超过 2 分钟、`RUNNING` 超过 135 秒的遗留任务结束并转人工，不无限重试外部调用。135 秒覆盖可配置的最大调用时限，避免管理员降低超时后提前终止旧请求。

外部消息的 `clientMsgId` 必须是 UUID，系统回复使用独立编号，避免用户占用内部回复编号。

## 验收方法

自动化测试使用本地模拟模型服务，不使用真实密钥、不消耗模型额度。执行后端 `mvn test` 和前端 `npm run build`，再进行浏览器验收。

1. 新建会话并提交首问，问题和回答各出现一次。
2. 连续追问，确认后端模型请求包含同一会话的有限历史。
3. 重复提交相同 `clientMsgId`，确认只生成一个任务和一条回答。
4. 模型延迟时切换会话、刷新、断线重连，等待状态和消息不串会话。
5. 生成过程中转人工，确认后续模型结果被取消，人工回复正常。
6. 模拟鉴权失败、限流、超时、空回答和不合法响应，确认等待结束，执行知识兜底或转人工。
7. 尝试关联他人订单、重放他人消息 ID，确认后端拒绝且没有数据泄露。
8. 检查日志只含脱敏摘要和错误分类，浏览器中不出现外部模型密钥。
9. 桌面和手机宽度检查长回答、输入框及聊天状态，确认没有横向溢出。

真实服务验收需要另外启用有效 SenseNova 配置，用测试内容完成首问和连续追问，并确认 `ai_call_log` 中存在外部模型的成功记录。仅通过构建、模拟接口测试或知识库答复，不能宣称真实 SenseNova 联调通过。

## 常见问题

- 首问一直等待：先确认数据库已升级、任务调度启用，检查任务状态和脱敏错误分类。
- 鉴权失败：确认使用的是 API Key 兼容接口，密钥属于当前账号且没有过期或被撤销。不要把旧版 AK/SK 当成 API Key。
- 模型不存在：将 `AI_MODEL_NAME` 改为账号已授权的模型 ID。
- 请求超时：检查本机网络和模型延迟，可合理调高时限；生成期间仍可转人工。
- 任务重启后结束为失败：过期任务按兜底流程处理，不自动重复外部请求。用户可在新的 AI 会话继续咨询。
